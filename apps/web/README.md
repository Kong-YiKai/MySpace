# Web Application

写实住宅看房与 AI 装修模拟器的可运行前端。默认从户型生成并锁定毛坯空间，再接受一张普通装修参考图或纯文字需求；参考图分析只作为 Aholo 3DGS 生成的内部输入，Aholo 多视角重建保留为可选专业入口。

## 当前实现

- React + TypeScript + Vite。
- React Three Fiber 只渲染锁定毛坯语义层与 Lux3D 浏览器降级叠加；真实整屋视觉层由 Aholo Viewer 加载 SPZ/PLY。
- 客户端户型图预检，拒绝格式错误或缺少平面结构特征的图片。
- 生成进度来自 SSE 与任务快照，展示真实 worldId、官方状态、最近更新时间和“官方暂无进度增量”。
- 3DGS 使用流式下载、格式识别、WebGL2/内存预算、低性能降级和明确失败码；不再用程序化精装占位。
- 第一人称从锁定入口开始，使用 `SpatialAnchorSet` 的可行走范围和墙体碰撞；支持键鼠与移动端触控。
- Lux3D 只选择一个最高优先级候选自动生成，通过 Scene Service 质量门后叠加并可点选。浏览器叠加不具备 3DGS 深度遮挡，UI 会明确标为 RenderCloud 前的受控降级。

## Iteration 3 渲染目标

- 以 Aholo Viewer 加载 Aholo 3DGS 空间，并在同一坐标系装配 Lux3D 生成的高保真 Mesh。
- 毛坯空间确认后锁定世界坐标、尺度、边界、门窗、入口和碰撞基线；前端不能用装修结果覆盖这些空间事实。
- 上传一张普通写实参考图可先触发内部风格提取；文字输入作为补充需求，在确认锁定并生成时自动合并；不要求普通用户提供全景或 20 张照片。
- 户型就绪后可直接点击「开始看房」，确认锁定空间并从入口漫游。装修需求、Lux3D 家具和 Aholo 写实 3DGS 都由用户按需提交。
- 优先展示 RenderCloud/Aholo 云端的 3DGS + Mesh 写实合成结果，并提供明确、可观察的浏览器直渲降级状态。
- 所有装修风格都必须写实；卡通、动漫、手绘、低多边形或明显游戏化结果直接判定为质量失败。

## 边界

- Web 只通过版本化 API、状态流和受控资产 URL 接入后端。
- 户型/实景识别、Aholo 重建、Lux3D 单体生成和 RenderCloud 任务均由 API/Worker 编排，前端只显示脱敏后的任务状态、结果和诊断证据。
- 手势识别通过独立计算服务输出高层输入事件，不把视觉模型耦合进渲染器。
